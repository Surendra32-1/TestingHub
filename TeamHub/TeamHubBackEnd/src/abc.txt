 Database guide — create / alter / seed
All of this is already written in the two schema scripts. You just need to run them in order against the TeamHub DB.
Tables to CREATE (idempotent — IF OBJECT_ID(... ) IS NULL / IF NOT EXISTS)
Table	Script	Purpose
dbo.EmployeeEducation	employee-education-training-schema.sql	per-employee education rows (FK → Employees, ON DELETE CASCADE)
dbo.EmployeeTraining	employee-education-training-schema.sql	per-employee training rows (FK → Employees, ON DELETE CASCADE)
dbo.Training	training-qualification-schema.sql	master catalog of training names
dbo.EducationalQualification	training-qualification-schema.sql	master catalog of qualification names
Columns to ALTER (also in employee-education-training-schema.sql, section 2b — adds only if missing)
EmployeeEducation.JoinedDateBS NVARCHAR(10) NULL
EmployeeEducation.PassoutDateBS NVARCHAR(10) NULL
EmployeeTraining.JoinedDateBS NVARCHAR(10) NULL
EmployeeTraining.PassoutDateBS NVARCHAR(10) NULL
These back the AD/BS dual-calendar feature. (If you created the tables fresh from the current script, the columns are already in the CREATE, so the ALTERs become no-ops.)
Seed to run
training-qualification-schema.sql → seeds EducationalQualification (SLC/SEE … PhD) and Training (Onboarding … Compliance & Ethics), idempotent by name.
employee-education-training-schema.sql (section 3) → one sample education + one training row per existing employee, idempotent via NOT EXISTS.
Note: seed-data.sql seeds the masters/employees but does not touch these 4 tables — they are seeded only by the two scripts above.
Run order (use this — dependencies matter)
1. databasesign.sql                 (base schema, already applied)
2. seed-data.sql                    (masters + 300 employees)
3. training-qualification-schema.sql  (create + seed the 2 master catalogs)
4. employee-education-training-schema.sql  (create/alter + seed per-employee rows)
Why this order: step 4's per-employee seed reads from dbo.Employees, so employees must exist first (step 2) or it inserts nothing.With sqlcmd (same pattern as the scripts' header):
sqlcmd -S ".\SQLEXPRESS" -d TeamHub -E -C -b -i seed-data.sql
sqlcmd -S ".\SQLEXPRESS" -d TeamHub -E -C -b -i training-qualification-schema.sql
sqlcmd -S ".\SQLEXPRESS" -d TeamHub -E -C -b -i employee-education-training-schema.sql
(Or run each GO-separated batch in DBeaver.)
Important gotchas
Re-running seed-data.sql wipes employees. EmployeeEducation/EmployeeTraining cascade-delete with them (FK ON DELETE CASCADE). After any employee re-seed, re-run step 4 to repopulate education/training.
The two master catalogs (Training, EducationalQualification) are currently standalone — the employee rows still store free-text Qualification / TrainingTitle and are not FK-linked to them. If you want the employee Education/Training forms to pick from these catalogs (i.e., store QualificationId / TrainingId), that's a further change: an ALTER TABLE to add the FK columns + backend entity/DTO/Dapper/frontend dropdown wiring.
